# 用 AI 帮你判断、构建和排错

先让 AI 帮你判断“用哪个”，再讨论“怎么装”。本项目没有通用的一键安装器，AI 也不能把源码 ZIP 自动变成匹配固件的安装包。

AI 只是可选助手，插件运行不需要 AI API Key。普通聊天窗口可以解释步骤和分析脱敏信息；只有具备相应权限的本机助手才能读取源码或执行本地检查。无法读取 GitHub 链接时，向它提供公开文档即可，不要发送设备备份。

## 第一步：选对路线和版本

复制以下提示词，把括号替换为你的目标：

```text
请先阅读 https://github.com/JasonBeam/openwrt-f50-plugins 的当前 README，
以及 docs/INSTALL.md、docs/VERSIONS.md、docs/PACKAGING.md。
如果你不能访问链接，告诉我需要提供哪些公开文档，不要猜测项目功能。

我的目标是【IPv6 RA 刷新 / 独立小鲸校正 / 已有 MU300 集成版修改间隔】。
请先解释我应该选择独立插件还是集成补丁，以及 Release 与 main 的区别。
给出判断兼容性所需的最少设备信息和只读检查命令，并说明每个命令的用途。

此阶段不要登录设备、安装软件、改配置、发起运营商查询、同步流量池或发送 RS。
不要索取卡号、验证码、密码、Cookie、私有 JSON 或完整备份。
不要根据设备名猜 IPK/APK 格式、WAN 网卡或 SDK，也不要保证全固件兼容。
```

你需要自己核对的通常是：系统是否真为 OpenWrt、固件与架构、实际包管理器、LuCI 版本、是否有 `unisoc.traffic`、是否已有同名服务。Android / UFI 版不直接套用 OpenWrt 教程。

设备输出若包含序列号、网络地址等信息，公开给 AI 或 Issue 前先脱敏。不要直接执行 AI 从其他机型推测出来的安装命令。

## 第二步：先在开发电脑检查源码

```text
请在我选择的 openwrt-f50-plugins 源码文件夹中工作。
先阅读 README 和 .github/workflows/check.yml，再检查本机 Python、Ruby、Node 是否可用。
仅检查公开源码，不读取下载的设备配置、卡号、私有状态或备份。

运行项目现有离线检查并汇报实际结果；缺少工具时先说明，不自动修改系统或路由器。
不要连接真实运营商，不部署文件，不创建 Release，不自动提交或推送。
区分“源码测试通过”“SDK 构建成功”和“设备安装验收通过”。
```

仓库现有检查在开发电脑上运行：

```sh
python3 -m unittest discover -s tests -p 'test_*.py' -v
ruby tests/test_xiaojing.rb
ruby tests/test_iot_interval.rb
```

Python 测试还会调用 Node、Ruby 和 Shell 做语法检查。测试使用模拟数据，不替代 SDK 或设备验收。

## 路线 A：让 AI 协助独立插件构建

```text
我准备构建【RA / 小鲸】独立插件。
目标固件、SDK 来源与提交、架构和实际包管理器是【填写已核对的信息】。
我使用【v0.1.1 固定源码 / main 的具体提交】，请核对 Makefile 和依赖。

先阅读 docs/PACKAGING.md，只在开发电脑的匹配 SDK 中安排构建。
不要把源码 ZIP 作为安装包，不手工改后缀，不直接复制到路由器覆盖服务。
RA 的 rdisc6 需要单独确认可信来源、许可和架构；
小鲸必须确认目标固件提供兼容的 unisoc.traffic，不能假设安装插件就会创建流量池。

如果缺少 SDK 或兼容信息，列出具体缺项，不编造构建成功。
若构建成功，汇报产物格式、实际路径、依赖和校验值，先给测试设备验收计划，不自动安装。
```

有 Makefile 不代表已经有安装包。生成 IPK 或 OpenWrt APK 取决于 SDK；`PKGARCH=all` 也不意味着跨固件通用。

## 路线 B：让 AI 协助已有集成版的离线补丁

```text
我的目标是已有 MU300 f50.iot 集成版的刷新间隔，不是独立小鲸插件。
请阅读 integrations/mu300/README.md 和 tools/apply_mu300_interval.py。
只处理我明确指定的离线源码目录副本，不连接设备、不读取私有凭据配置。

先检查四个目标文件和已知锚点是否匹配；不匹配或已打补丁时停止，不强行替换。
确认匹配后，在新的离线副本中使用现有工具生成补丁，展示差异并检查 Ruby、JS、JSON。
核对新增文件和原有配置的保留范围，不把独立插件复制进旧流量池。
不要上传、重启服务、同步流量、改额度或历史。
```

工具入口是 `python3 tools/apply_mu300_interval.py /path/to/staged-root`，其中路径必须是你准备的离线根目录副本。它会写入副本中的文件，不是只读预览；不要直接指向设备或把 `/` 当作目标。

集成版输入 **5–1440 整数分钟**，独立插件输入 **300–86400 秒**，默认都对应 20 分钟。让 AI 说明当前路线和单位，避免将 20 当成秒数保存。旧集成代码的 HTTP 行为不会因间隔补丁自动得到独立插件的 HTTPS 默认策略。

## 遇到问题时，给 AI 什么信息

```text
使用项目：JasonBeam/openwrt-f50-plugins
源码版本 / 提交：【版本或短提交号】
路线：【独立 RA / 独立小鲸 / MU300 集成补丁】
失败阶段：【SDK 构建 / 测试设备安装 / LuCI 显示 / 配置保存 / 状态读取】
固件、架构、包管理器：【脱敏信息】
操作步骤与脱敏错误：【不含凭据的必要片段】

请根据对应版本源码定位原因，先给最小的只读检查，不执行修复。
不要建议 --force 安装、关闭证书校验、扩大 rpcd 权限或清空流量池来试错。
不索取卡号、验证码、Cookie、SSH 密码、私有文件或完整设备备份。
证据不足时说明缺少哪类脱敏信息，不假装远程验证过。
```

`--status` 是状态读取；小鲸 `--preview` 会向平台发送真实凭据查询，并非离线检查。`--sync` 会校正真实流量池；RA 的 `--once` / `--force` 可能发送 RS。这些操作不能被 AI 当成无影响的“看看”。

## 最后由使用者验收

- 下载对象、源码提交、包版本与固件对应，独立插件和集成补丁没有混装。
- 默认关闭、启用、失败回退及配置保留符合预期；更新没有清空流量池历史。
- RA 续期有实际路由回读证据，不只看工具退出码；平台查询成功不当作实时账单。
- 文案中的“测试通过”明确指哪种检查，没有把模拟结果写成 SDK 或设备实测。

使用前阅读[安装说明](INSTALL.md)，发布前阅读[验收计划](ROADMAP.md)。未经核对，不在唯一上网设备上试装。
